# #181 依赖线束组合回归与实图验收

日期 2026-10-27，WSL2 + WSLg，renderer D3D12（GTX 1080 Ti）/ wgpu Gl。
实现基线为 `integration/spec-172` 256d98af；spec 之前的基线为 556da744。

## 组合回归

- `crates/viewer/tests/bundle_acceptance.rs` 使用 `fixtures/bundle_acceptance.ir.edn`。
  根层同时包含跨 rank 主干（App 扇出）、违规主干、因安全规则回退的依赖、反向边和关联边；
  `ui` 子层有三成员主干；提案根层及 Shell 层也有主干。每个当前视图都检查：
  每对有向可见端点只有一条逻辑边，保留 leaf 明细和头部；主干只承载同违规样式的普通依赖，
  不含反向成员；分支起止点与基础路径一致；主干只画一次且没有自己的头部；
  主干和分支的命中、弹窗、直接悬停、离开清除、依赖链（独立按 leaf BFS 推导）
  以及违规红色。覆盖钻取/返回、提案及下一层、五档 declutter、Remove arrows、
  同内容热重载和相机变化。
  断言阈值来自规格，不来自时点数量；对 `commands.rs` 链判定和 `hit.rs` 主干命中
  人为改坏时，测试分别失败。
- `scripts/drivers/bundle_acceptance.edn`（已注册到 `check.py --native`）在真实窗口重放上述组合；
  本目录 `acceptance-*.edn/png` 是该 driver 的输出。
- `bench_scene.rs`：2000 类和 500 类的计时编译都必须产生非空主干，每名成员都有分支
  （注释掉 `bundle::plan` 后两项失败）。新增平行边压力：240 条平行依赖必须形成真实主干，
  与同布局、不成线束的 association 孪生场景比较，规划开销须小于 2 倍（实测 1.00–1.12 倍）。

## 真实窗口性能协议（`bench/run_rust.sh`）

摘要见 `bench/`。阈值未改动。基线与 HEAD 使用同一协议脚本和同一机器，`UML_BENCH_MAX_LOAD=2.0`，
开始前最多等待负载降到 2.0。全部 7 次运行的 renderer 都是 D3D12（NVIDIA GeForce GTX 1080 Ti），
backend 都是 Gl；有效运行的起止负载都在 2.0 以内。

- 原协议判定：HEAD 两个有效运行均为 **FAIL**（500 要求 ≥58 fps 且 p95 ≤18.3 ms；
  2000 要求 p95 ≤33.3 ms）。idle CPU 和 D3D12 两项通过。
- 同条件基线：556da744 同样 **FAIL**，而且本机当天差距远大于 #143 记录（2000 类 p95 约
  144–213 ms，历史约 26–40 ms）。这是本次测量前已经存在的差距，不是线束导致的。
- 线束新增变化：500 类均值帧时间约 46–47 → 49–54 ms（约 +5% 至 +15%），
  2000 类约 131–146 → 141–149 ms（约 +2% 至 +7%）；p95 有升有降。每种配置只有一次有效样本，
  VOID 由 viewer 自身负载与本机其他会话叠加造成，因此这些变化不能与噪声明确区分。

## fs-monopoly 实图（人工证据）

`fs-monopoly/` 中前后截图使用同一份现成 IR（`fs-monopoly/tmp/uml/fs-monopoly.edn`，
sha256 `7f81a996…3fba`，未重新生成，也未改动该仓库）。before 由 556da744 产生，
after 由本分支产生，驱动脚本相同（after 只额外 dump 画布）。

- 端点：以 `scene` 投影比较，根层 33 条和 Ui 层 35 条逻辑边的 from/to/kind/points/tip/behind/curve
  与类布局均完全一致；线束只新增 `:branches`/`:bundles`。
- 根层：适配缩放下变化很小，只有 3 个两成员主干（App→Host、Computer 上方、State 右上），
  左侧最密集的纵向通道未成线束。视觉拥挤**没有明显改善**。
- Ui 层：6 个主干、10 条边改走分支。部分曲线改成直角折线，下方出现多处小方框形折返和
  极短分支（约屏幕 x 440/630/710、y 595 附近以及 Schema 下方）。整体拥挤**没有明显减轻**，
  局部可读性反而变差。
- 结论：线束不改变端点、头部或逻辑事实，但在这份真实图上没有达到 #172「更快辨认结构」
  的视觉目标，需要在整体 review 中处理。

## 已知非阻断问题的观察

- 完全共线主干无成员上限：组合 fixture 和 fs-monopoly 中未观察到超过 4 名成员的主干。
- 相接区间产生极短分支：**观察到**。提案 Shell 层出现同成员的连续两段主干（[6 7] 两次），
  截图中有小方框折返；fs-monopoly Ui 层也有同类折返。根层跨 rank 主干只有 16 px，
  位于包框外侧。
- 交叉检查为折线近似：未发现由此导致的新交叉误判。
- 另一项观察：同布局的平行扇出超过约 60 组后，布局会换行，全部候选回退，没有主干。
