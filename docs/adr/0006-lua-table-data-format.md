# 0006 数据文件改用 Lua 表字面量，退役 EDN

**Status**: accepted；实现尚未开始（当前代码仍读写 EDN，规格见 #89）

所有持久化数据（policy、生成的 IR、邮件队列、viewer/companion 状态、质量快照）都是 EDN。EDN 由 viewer 内一个 176 行手写解析器承担，不为技术栈增加一门语言，但生成物是不可审阅的单行文本：示例 IR 约 45 KB 只有一行数据，git 里每次重新生成都表现为整行替换，任何改动都无法 review。这次核查就是一例：仓库里那份 IR 是在一个临时 worktree 中生成的，`policy-file` 指向已删除的绝对路径，且落后源码五个模块，直到逐字段比对才被发现。更糟的是两次生成连字节都不稳定——顶层 map 由 `pairs()` 构造，键序不固定：同一份源码连续两次 `ir` 得到不同顺序的顶层键（语义相同，已实测）。决定把所有自有数据文件改为 `return { ... }` 形式的 Lua 表字面量，读取使用只读的子集解析器（不使用 `dofile`，因为文件由 agent 与邮件驱动，属于不可信输入），写入按"类按层级、边按端点排序、op 按源文件行号"分多行输出，顶层键按 schema 声明序固定。外部质量工具（crapper、mutator、dryer）同为本人维护，同步改用同一格式；格式规范由四端各自测试固定。切换为一次性切换，不发布兼容层。完整规格与批次划分见 #89。

## Considered Options

- **保留 EDN，只换解析器**：无法解决单行生成物的可审阅性问题，而这是唯一可量化的收益。
- **`dofile` 加载数据**：省去解析器，但把每个数据文件变成可执行代码；一次写坏或一次注入即任意代码执行。
- **只转换手写产物（policy、邮件），保留生成的 IR 为 EDN**：需要同时维护两种解析器，与"精简"目标相反。

## Consequences

- EDN 的 keyword / symbol / 有序 map / nil 哨兵四种概念取消：键是 snake_case 裸标识符，值是字符串、布尔、数字或嵌套表；`foreign` 原先的符号、keyword、字符串三形态归一为字符串。
- 现有安装升级后，旧 policy 与运行态文件不再被读取。policy 报错并给出改写示例；运行态文件归档丢弃，正在进行的会话视图与邮件游标不保留。
- 冻结的 JVM 对照基线转为 Lua 表后重新基线，不再与 JVM 实现可比，仅作为几何回归预言机。
- 数据文件里出现无法解析的构造时立即失败并给出行列位置；此前分层 IR 绕过校验，坏数据要到渲染阶段才暴露。
